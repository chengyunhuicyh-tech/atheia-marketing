# Monthly Plan — Atheia
One command that turns "plan {month}" into a filled-in monthly plan written to Notion, plus the actual deliverables for whichever channels are active this month — generated by handing off to the right channel skill, not by improvising inline.
This skill is the **orchestrator**. It doesn't replace `emails`, `ads`, `ad-creative`, `social`, `popups` — it sequences them, with everything anchored to the same durable brand context so nothing drifts.
## Step 0 — Load durable context (always, first)
Read `.agents/product-marketing.md`. This is Atheia's foundation: brand hooks, products, audience, channel doctrine (permanently IN / OUT / KIV), budget envelope, visual system, voice, hard-won learnings, recurring rhythms, operating constraints.
Everything generated this month must respect it — especially:
- **The permanent cut-list** (§5) — don't reintroduce WhatsApp, Klaviyo, heavy email cadence, gifting-for-posts, or cold-Meta-as-sales.
- **The hard-won learnings** (§8) — ads → PDP, cold judged on CPC + followers only, capture pop-up contacts at checkout, etc.
- **The 2-person, can't-film-themselves production constraint** (§10).
If this file is missing, stop and tell the user — don't generate a plan without it. That's exactly how the Notion/file drift from before happened: a plan written without the current source of truth.
## Step 1 — Pull last month's carry-ins
Search Notion for last month's `📅 {Previous Month} — Month Overview` page and read its "End-of-month reflection" block (What worked / What didn't / Carry into next month). If it's unfilled or doesn't exist, ask the user for a quick verbal version: "anything from last month to double down on, drop, or test?"
## Step 2 — Gather the Monthly Input Brief
Use `references/input-brief.md` as the question set, but **don't ask everything** — infer what's already knowable:
- Starting numbers → pull from last month's "Numbers vs target" table if filled in.
- Channel doctrine → already fixed by the context file; only ask about *exceptions* this month.
- Budget → default to the context file's confirmed envelope (§6) unless the user says otherwise.
Ask only the genuine decisions for this month: is there a sale, are pop-ups confirmed, is UGC/affiliate switching on, any capacity flags. Aim for 3–5 questions in one batch, not a long interview.
## Step 3 — Generate the plan
Follow `references/plan-template.md` for the section structure and the generation rules. Output is Notion-paste-ready markdown — H2 headers, tables for anything structured, checkboxes for todos.
## Step 4 — Write the plan to Notion
1. Find `🗂️ Atheia Social — Campaign Hub`.
2. Duplicate last month's `📅 {Month} — Month Overview` page via `notion-duplicate-page` — this carries over its sub-page structure (Campaign Strategy, Content Tracker, Stories plan) so the shape stays consistent month to month.
3. Rename the duplicate to `📅 {New Month} — Month Overview`.
4. Replace its content with this month's generated Theme / Targets / Budget / 5 Priorities / End-of-month reflection scaffold (cleared, not copied from last month).
5. Replace the duplicated `🎯 Campaign Strategy` sub-page content with this month's Channel plan / Sale structure / Week-by-week todos / Founder stagger plan.
6. Note for the user: the Content Tracker's month-view filter (Scheduled is within the new date range) needs rebuilding — this is a database-view action that's easiest done by hand in Notion.
If Notion tools aren't available in this session, write the plan to a local markdown file instead, tell the user where, and give paste-in instructions.
## Step 5 — Fan out to channel skills
This is the step that actually produces the month's assets. **Only fan out to a channel if this month's plan calls for output from it** — don't generate UGC briefs if UGC is KIV this month, don't generate sale ad creative if there's no sale. Respecting the doctrine here is as important as respecting it in the plan itself.
For each applicable row, spawn a subagent (Task tool) pointed at the named skill. Give each subagent only what it needs — not the whole context file:
- The relevant excerpt of `.agents/product-marketing.md` (brand snapshot §1, visual system §7, voice cues, and the channel doctrine row that applies to it)
- The relevant section of this month's generated plan (its channel's part only)
- The specific deliverable(s) requested
| This month's plan includes... | Skill to invoke | Deliverable |
|---|---|---|
| A sale | `emails` | Sale-launch + last-call broadcast copy — plain text, founder voice, tier-led per the sale philosophy in §9 |
| A sale | `ads` + `ad-creative` | Meta sale ad variants (tier-led / fabric-led / urgency-led), destination always the PDP |
| Any month | `social` | This month's carousel set + Stories day-by-day plan, per the content cadence in §9 |
| Pop-up(s) confirmed | `popups` | Pop-up booth checklist + BFT member-comms asset pack |
| UGC switched on | `social` (or `video` if wired) | UGC creator brief scoped to this month's product focus |
| Affiliate switched on | — (no dedicated skill yet) | Generate DM templates + tracking sheet inline |
Run these in parallel where the tooling allows. Each subagent's output should land as a file or a Notion page/database row — not just chat text — so it's discoverable from the Content Tracker afterwards.
## Step 6 — Wrap-up
- Summarize what was generated and where: Notion links + any local files.
- Remind the user of the items that still need a human: confirming pop-up logistics with BFT, setting the 2 broadcast send dates, rebuilding the Content Tracker filter.
- Don't mark anything as sent, posted, or live — this skill drafts, it doesn't execute.
## Guardrails (apply throughout — not just Step 3)
These are restated from `.agents/product-marketing.md` §5–8 because the Step 5 subagents won't necessarily read the whole context file themselves:
- **Sale comms are tier-led** ("buy more, save more"), never discount-led ("everything on sale").
- **Every sales ad destination is the product page** — never the IG profile or homepage.
- **Cold Meta is judged on CPC + followers only** — never proposed as a sales channel.
- **Every deliverable must be executable by 2 founders who can't film themselves** — Canva + phone + CapCut by default; anything needing more becomes a paid-creator brief, not a DIY task.
- **Currency is always `SGD $` or `S$`.** Voice, hashtags, and photo cues follow the visual system in §7.
- **Don't pretend budget exists** — confirmed vs. conditional spend stays explicit in everything generated.
## Month-end (separate invocation)
At month-end — "wrap up {month}" or `/monthly-plan {month} --reflect`:
- Open this month's Month Overview and fill the reflection block (What worked / What didn't / Numbers vs target / Carry into next month).
- If a new durable learning emerged, add it to `.agents/product-marketing.md` §8 **and** the canonical Notion 📖 Marketing Context page. Keep both in sync — that file's header has the sync note. A learning that only lives in one place will quietly drift out of the other, which is the exact problem this whole setup exists to avoid.
